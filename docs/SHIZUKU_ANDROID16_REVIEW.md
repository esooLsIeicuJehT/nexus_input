# Shizuku Android 16 injection review

**VERIFIED — source review:** PR #6 is merged. This follow-up retains its correct API-34 boundary and the existing UserService/AIDL architecture. **UNKNOWN:** physical Android 16/OEM game injection remains untested in this environment. A successful build or bridge self-test is not hardware verification.

## Framework and service contracts

- [Android 13 InputManager](https://android.googlesource.com/platform/frameworks/base/+/android-13.0.0_r1/core/java/android/hardware/input/InputManager.java) resolves the binder through ServiceManager. [Android 14 InputManager](https://android.googlesource.com/platform/frameworks/base/+/android-14.0.0_r1/core/java/android/hardware/input/InputManager.java) instead requires ActivityThread.currentApplication().
- [Android 14](https://android.googlesource.com/platform/frameworks/base/+/android-14.0.0_r1/core/java/android/hardware/input/InputManagerGlobal.java), [15](https://android.googlesource.com/platform/frameworks/base/+/android-15.0.0_r1/core/java/android/hardware/input/InputManagerGlobal.java) and [16 InputManagerGlobal](https://android.googlesource.com/platform/frameworks/base/+/android-16.0.0_r1/core/java/android/hardware/input/InputManagerGlobal.java) expose getInstance/injectInputEvent without requiring a normal Application process.
- [Official Shizuku UserService documentation](https://github.com/RikkaApps/Shizuku-API/blob/a27f6e4151ba7b39965ca47edb2bf0aeed7102e5/README.md) describes UID 0/2000, unrestricted hidden API access and the absence of a normal application process.
- [AOSP injection synchronization contract](https://android.googlesource.com/platform/frameworks/native/+/f982044859e939e488967562b2d64f00f7ec1504/libs/input/android/os/InputEventInjectionSync.aidl) defines NONE=0, WAIT_FOR_RESULT=1, WAIT_FOR_FINISHED=2. NONE is documented as asynchronous and assumed successful. [Android 16 InputDispatcher](https://android.googlesource.com/platform/frameworks/native/+/android-16.0.0_r1/services/inputflinger/dispatcher/InputDispatcher.cpp) returns unconditional SUCCEEDED after enqueueing in NONE mode. This follow-up uses WAIT_FOR_RESULT and propagates actual false/exception results. Acceptance is a dispatcher result, not proof that a game acted on the touch.
- [UserServiceArgs.version documentation](https://github.com/RikkaApps/Shizuku-API/blob/a27f6e4151ba7b39965ca47edb2bf0aeed7102e5/api/src/main/java/rikka/shizuku/Shizuku.java) requires a changed version when service code changes; [the server](https://github.com/RikkaApps/Shizuku-API/blob/a27f6e4151ba7b39965ca47edb2bf0aeed7102e5/server-shared/src/main/java/rikka/shizuku/server/UserServiceManager.java) reuses live same-version services. Implementation version is now 4; the stable tag and AIDL transaction order are preserved.
- [Android 16 MotionEvent](https://android.googlesource.com/platform/frameworks/base/+/android-16.0.0_r1/core/java/android/view/MotionEvent.java) supplies default display 0 for the existing obtain overload. This review found no missing primary-display ID fix. **UNKNOWN:** external-display mapping is not supported or verified by this change.

## Observable failure and preference fixes

**VERIFIED — source:** resolver failures reach selfTest as ERROR instead of killing initialization before the binder can report the cause. Reflection unwraps the actual framework exception. BRIDGE_ONLY diagnostics report the selected bridge, SDK, dispatch mode and service implementation version; they never inject a test touch. Successful details reach logs and the runtime notice.

**VERIFIED — source:** failed/stale/dead handshakes cannot become cached success; expired bind callbacks cannot publish a remote; cached connects recheck the handshake. Failed UP cleanup retains the service for panic retry, and service loss with unconfirmed contacts cannot silently start a new gesture. Adapter cleanup failure retains its resource and remains observable.

**VERIFIED — source:** System displays the profile's requested backend, rather than the globally preferred available backend. Explicit Shizuku selection and Automatic reset persist through Room. Save failure restores the previous optimistic value without overwriting a newer edit. Forced choices still fail closed. The floating controls show actual runtime failure/notice/foreground/connection observations and preserve the original error when an edit cannot start.

**UNKNOWN — overlay/OEM limits:** primary-display pointer IDs, gesture timing and action indices match AOSP contracts, but actual device delivery still needs testing. Crosshair/FPS windows each use alpha 0.7; if their bounds overlap, combined opacity is 0.91, above the usual 0.8 untrusted-touch budget. [WindowManager contract](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#FLAG_NOT_TOUCHABLE). No fabricated device opacity or blanket OEM compatibility claim is made here. Run the initial input test with these overlays off.

## Focused real-device acceptance (all NOT_RUN here)

1. Back up profiles. Install the new debug APK only if its certificate matches the installed build, or use the original-key signed workflow. An install signature conflict is not permission to erase app data.
2. On the actual non-root Android 16 device, start Shizuku, authorize Nexus and enable Nexus accessibility capture and overlay permission. Verify the controller tester records actual buttons/axes. SDK 34+ is required for global stick motion capture.
3. Load the affected profile. In System inspect its requested backend, explicitly choose Shizuku and wait for the actual save acknowledgement. Launch its exact saved game package. Open floating controls and record the actual foreground, backend notice and errors.
4. Expected diagnostic fields (not captured results): uid=2000, bridge=InputManagerGlobal, sdk=36, mode=WAIT_FOR_RESULT(1), probe=BRIDGE_ONLY, serviceVersion=4. UID 0 is a separate rooted/Sui test, not proof of non-root Shizuku.
5. With crosshair/FPS off, bind one face button to an unmistakable game control, then exercise actual DOWN/UP. Record game response and logs. Authorization/bridge initialization alone is not a pass. If rejected, retain the original ERROR/SecurityException/timeout and InputDispatcher logs.
6. Test HAT diagonals/neutral, analog plus key trigger HOLD, simultaneous independent LS/RS and face buttons, then panic/focus loss/rotation/disconnect. Confirm real release, no stale gestures and visible failure on binder death. Repeat with overlays enabled and record any occlusion rejection.
7. Stop/restart Shizuku while a contact is held. Confirm unconfirmed release is not relabeled successful and mapping cannot reconnect into an unresolved gesture. Restarting the app is not touch-release proof.
8. Force Accessibility in a test copy of a persistent-touch profile: it must visibly reject that requirement. Explicitly save Shizuku, relaunch and retest. Automatic selection is an explicit user choice, never a hidden repair.

Use [the read-only collector](../scripts/device_test_v1.py) and [full device checklist](DEVICE_TEST_CHECKLIST_V1.md). Attach actual diagnostics JSON, logcat, APK checksum/certificate, Android/OEM build, Shizuku version and recorded game response. Source/fixture tests do not certify this checklist.
